00 · How to run this program

Read this page once. It works like the rules of a programming language: every procedure after it follows them.

The rules

  1. One procedure at a time. Finish it, or stop it cleanly, before starting another. Never run two at once.
  2. Run the steps in order. Don't skip a step because it "looks obvious". If a step says copy, copy; don't retype.
  3. Tick each ☐ with a pen as you finish it. If you stop halfway, the last tick tells you where to resume.
  4. Check the EXPECTED OUTPUT at the end of each procedure. If what you see matches, the procedure is done.
  5. ON ERROR, stop. Don't improvise. Take a screenshot, then send Claude the error template from the Appendix (section 10).
  6. Secrets never go into chat, email, WhatsApp or the repo. A secret is any value this document labels SECRET. Keep them in a password manager (Apple Passwords, 1Password or Bitwarden).

How to read a procedure

PROCEDUREThe name of the task, like a function name.
WHYWhat it achieves, in one sentence.
INPUTSWhat you need before you start. If you don't have every input, don't start.
TIMERoughly how long it takes.
STEPSNumbered actions, done in order.
IF / ELSEA fork: do the branch that matches what you see.
EXPECTED OUTPUTWhat "done" looks like.
ON ERRORWhat to do when it doesn't work.

Notation

  • Bold text in steps = a button, menu or label to click on screen, spelt exactly as it appears.
  • Grey monospace = text to type or paste exactly, character for character.
  • <LIKE_THIS> = a placeholder. Replace the whole thing, including the < >, with your own value.
  • → = "then click". Settings → Domains means click Settings, then click Domains.
  • "Terminal" = the Mac app called Terminal (press ⌘ + Space, type Terminal, press Enter).

03 · test_school_as_learner() DO NOW · weekends

PROCEDURE test_school_as_learner(course) → bug reports
WHYYou're the first real learner. Things you trip over will trip up every learner after you.
INPUTSYour phone and a laptop. The school: school.scribsandpixels.com
TIME20–40 minutes per session. Repeat any weekend.
Know this first: progress is saved in this browser only. A different phone or browser, a private tab, or clearing site data starts you from zero. That's expected until accounts exist.
Checkpoints are strict: once you press Start checkpoint, leaving, reloading or closing the page counts as a failed attempt (60-minute cooldown). Start only when you have 10 calm minutes.
  1. Open the test site on your phone.
  2. Tap one course. Choose one per session: Fullstack, French or Excel.
  3. Open the week you're actually on, then today's day.
  4. Do the day as a learner: read, open the links, tick blocks, do the quiz, use any sandbox, write the log.
  5. While doing it, note anything in these 5 bug types:
    • BROKEN: an error, a blank screen, a button that does nothing.
    • WRONG: a wrong quiz answer, a wrong number, a typo, a dead link.
    • CONFUSING: you didn't know what to do next.
    • UGLY: overlapping text, too small on the phone, bad colours.
    • SLOW: you waited more than 3 seconds.
  6. For each bug: take a screenshot, then copy the address bar (the bit after #/ says exactly which page).
  7. Optional, to test checkpoints quickly: tap the round 🧪 button (bottom right of the screen) → Force checkpoint on this day. To skip a 60-minute cooldown: End cooldown now.
  8. IF you want to start a course again → 🧪 → Reset my progress → OK. ELSE leave it.
  9. Send all bugs from the session in one message, using the bug template in section 10.
EXPECTED OUTPUT: One message to Claude listing your bugs. Claude fixes them and replies with what changed.
ON ERROR: If the whole site is blank, reload once. If it's still blank, try another browser. If it's blank everywhere, send Site is blank on <device/browser> with a screenshot.

06 · connect_subdomain() ✓ DONE 9 Oct

PROCEDURE connect_subdomain(domain) → school.<yourdomain>
WHYA clean address like school.scribsandpixels.com instead of the long GitHub one.
INPUTS(a) 05 done. (b) A login to the company that holds your domain (the "registrar" or DNS host, e.g. Namecheap, GoDaddy, Cloudflare, Whogohost). (c) The exact domain and the subdomain you want.
TIME15 minutes, then up to 24 hours for the internet to catch up
  1. Decide the address, e.g. school.<yourdomain>. Done: school.scribsandpixels.com
  2. In Vercel: open the project → Settings → Domains → type the address → Add.
  3. Vercel shows a record to create. It's usually: Type CNAME, Name school, Value cname.vercel-dns.com. Copy what it shows if that's different.
  4. Log in to your registrar → find DNS / DNS Records / Advanced DNS for the domain.
  5. Add record → fill in exactly the Type, Name and Value from step 3. Leave TTL on Automatic → Save.
    IF your registrar is Cloudflare → set the orange cloud (proxy) to grey / DNS only.
  6. Back in Vercel → Domains. Wait until the status says Valid Configuration (a refresh every few minutes is fine).
  7. Open the new address in your phone browser.
  8. Send Claude: Subdomain live: <address>. Make it the main host and update APP_URL references.
EXPECTED OUTPUT: The school opens at your subdomain with a padlock (https).
ON ERROR: "Invalid configuration" after 24 hours → screenshot the registrar's DNS page and Vercel's Domains page, and send both. Don't delete other DNS records: they run your email and main website.

07 · create_supabase_project() ON HOLD

PROCEDURE create_supabase_project() → database with tables + 2 keys
WHYSupabase will store learners' accounts and progress, so progress follows you across devices. Only useful once Claude wires accounts into the app.
INPUTSA GitHub login, a password manager, and the Mac with this project.
TIME25 minutes
  1. Go to supabase.com → Start your project → Continue with GitHub.
  2. New project. Name: scribsandpixels-school. Region: West EU (London) or Central EU (Frankfurt), the closest to Lagos. Plan: Free.
  3. Database Password: click Generate a password → save it in your password manager as SECRET "Supabase DB password" → Create new project. Wait about 2 minutes.
  4. Open the Terminal and check the Supabase tool runs. Nothing to install: npx (part of Node, already on the Mac) fetches it the first time, which takes about a minute. 
    cd ~/Desktop/scribsandpixels-school
npx supabase --version
    It prints a version number such as 2.120.0. If it asks Ok to proceed? (y), type y and press Enter.
    Every Supabase command below starts with npx. Don't use brew install supabase: on this Mac it fails with "Command Line Tools are too outdated".
  5. Log in from the Terminal (a browser window opens; approve it): 
    npx supabase login
  6. In Supabase: Project Settings (gear icon) → General → copy Project ID (the "project ref", 20 letters).
  7. In the Terminal, go to the project and link it (paste your ref; type the DB password when asked): 
    cd ~/Desktop/scribsandpixels-school
npx supabase link --project-ref <PROJECT_REF>
  8. Create all the tables (this runs the migration file Claude wrote): 
    npx supabase db push
    When asked Do you want to push these migrations? type Y and press Enter.
  9. In Supabase: Table Editor. You should see tables including profiles, enrollments and quiz_attempts.
  10. Get the two values. Both are safe for the browser.
    • Project URL: already known, no need to look it up: https://ookbfjjsnzgbrcgltkot.supabase.co (it's https:// + your project ref + .supabase.co).
    • Publishable key: left sidebar → Project Settings (gear icon, bottom) → API Keys. Copy the key that starts with sb_publishable_ (click the copy icon next to it).
      IF there's no sb_publishable_ key → open the Legacy API Keys tab and copy anon (a long key starting with eyJ). Either works.
    • Never copy sb_secret_… or service_role: those are secret.
  11. In the Terminal, create the local settings file: 
    cp .env.example .env.local
open -e .env.local
    Replace the two placeholder values with your URL and anon key → save (⌘S) → close.
  12. Tell Supabase where the school lives, so login emails link to it (not to localhost): Authentication → URL Configuration.
    • Site URL: https://school.scribsandpixels.com → Save
    • Redirect URLs → Add URL, one at a time: https://school.scribsandpixels.com/**, https://scribsandpixels-school.vercel.app/**, http://localhost:5173/**
  13. Give the live site the same two values: Vercel → the project → Settings → Environment Variables. Add VITE_SUPABASE_URL = your Project URL, and VITE_SUPABASE_KEY = the anon / publishable key (environments: all) → Save. Then Deployments → the top one → ⋯ → Redeploy.
  14. Send Claude: Supabase project created and migrated. .env.local is filled in. (Don't paste any keys.)
NEVER copy the service_role key anywhere except the password manager. It bypasses all security. If it ever leaks: Supabase → API settings → roll (regenerate) it.
EXPECTED OUTPUT: The tables are visible in the Table Editor, and .env.local holds two real values.
ON ERROR: If npx supabase db push prints red text → copy the whole Terminal output (⌘A, ⌘C) → send it to Claude. Don't run it again repeatedly.

08 · set_up_resend() ON HOLD

PROCEDURE set_up_resend(domain) → verified sending domain + API key
WHYResend sends the daily nudge and Sunday review emails, from an address on your own domain.
INPUTSA registrar/DNS login (as in 06) and a password manager.
TIME20 minutes, then up to a few hours for verification
  1. Go to resend.com → Sign up (the free plan is enough).
  2. Domains → Add Domain → type your domain, e.g. <yourdomain> (or a subdomain like mail.<yourdomain>) → choose the region closest to you → Add.
  3. Resend shows 3–4 DNS records (TXT, MX, DKIM). For each one: registrar → DNS → Add record → copy Type, Name and Value exactly → Save.
  4. Back in Resend → Verify DNS Records. Repeat every 15 minutes until every row is green / Verified.
  5. API Keys → Create API Key. Name: school-nudges. Permission: Sending access → Add.
  6. Copy the key now (it starts with re_ and is shown only once) → save it in your password manager as SECRET "Resend API key".
  7. Decide the From address, e.g. Scribs & Pixels <school@scribsandpixels.com>. Write it here: ______________________
  8. OPTIONAL, for login emails from your domain too: Supabase → Authentication → Emails → SMTP Settings → enable custom SMTP: host smtp.resend.com, port 465, username resend, password = your Resend API key, sender = your From address → Save.
EXPECTED OUTPUT: The domain shows Verified in Resend, and the API key is in your password manager.
ON ERROR: If records won't verify after 24 hours → screenshot Resend's domain page and your DNS page, and send both. A common cause is the registrar adding your domain to the Name automatically (e.g. send.yourdomain.com.yourdomain.com): type only the part Resend shows before your domain.

09 · deploy_email_nudges() ON HOLD

PROCEDURE deploy_email_nudges() → hourly emails running
WHYSwitches on the daily nudge (Mon–Sat, at each learner's chosen hour, only if they haven't studied) and the Sunday review digest.
INPUTS07 and 08 done. Your project ref, Resend API key, From address, and the site address (APP_URL: https://school.scribsandpixels.com).
TIME20 minutes
  1. Make a cron password in the Terminal and save the output in your password manager as SECRET "CRON_SECRET": 
    openssl rand -hex 32
  2. Set the four secrets. Paste this as one command after filling in the four placeholders; keep the quotes: 
    cd ~/Desktop/scribsandpixels-school
npx supabase secrets set RESEND_API_KEY="<re_...>" EMAIL_FROM="Scribs & Pixels <school@scribsandpixels.com>" APP_URL="https://school.scribsandpixels.com" CRON_SECRET="<from step 1>"
  3. Upload the email function: 
    npx supabase functions deploy send-nudges --no-verify-jwt
  4. Do a safe dry run, which shows what would be sent without sending anything (replace both placeholders): 
    curl -s -X POST "https://<PROJECT_REF>.supabase.co/functions/v1/send-nudges?dry-run" -H "Authorization: Bearer <CRON_SECRET>"
    IF it prints JSON (even an empty list) → continue. ELSE IF it says Unauthorized → the CRON_SECRET doesn't match step 2; redo step 2.
  5. In the project folder, open supabase/setup/schedule-nudges.sql in TextEdit. Don't save changes to it; you'll paste a filled-in copy instead.
  6. Copy its whole content. In Supabase → SQL Editor → New query → paste.
  7. In the pasted text only, replace <project-ref> with your project ref and <CRON_SECRET> with your cron secret.
  8. Click Run.
  9. Check it's scheduled: new query → select jobname, schedule from cron.job; → Run. You should see send-nudges with 0 * * * *.
  10. Send Claude: Nudges deployed and scheduled. Dry run returned <paste the output>.
EXPECTED OUTPUT: The cron job is listed and the dry run returns JSON. Real emails start once learners have accounts.
ON ERROR: If the SQL editor says secret already exists, you ran the script twice. Send Claude the message; don't try to delete vault secrets yourself.

Words

RepoThe project's folder on GitHub: github.com/VictorAnimasahun/scribsandpixels-school. Claude pushes every finished change to its main branch.
DeployPutting the latest version on the internet. GitHub Pages does it automatically about 2 minutes after each push.
DNS / recordThe internet's address book. A CNAME record says "this name points to that server".
RegistrarThe company you bought the domain from. That's where DNS records are edited.
MigrationA file that creates database tables. Running it twice is safe for Supabase; it skips what's done.
Secret / keyA password for a service. "anon/publishable" keys are safe in the browser. "service_role", the Resend API key, CRON_SECRET and the DB password are SECRET.
Edge functionA small program that runs on Supabase's servers. Here: send-nudges, the email sender.
CronA timer. 0 * * * * means "every hour, on the hour".
Dry runA rehearsal that shows what would happen without doing it.
